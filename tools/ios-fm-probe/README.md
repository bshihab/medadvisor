# iOS FM Probe — measure the stock OS-27 model on the real phone

Answers the one Apple-model question that is **not** blocked by Apple's retired
adapter toolkit: **is the rebuilt iOS 27 on-device model good enough to grade
the rubric on its own?** Apple describes it as "rebuilt from the ground up,
better across the board" — and our damning stock numbers (54.3% accuracy, 75%
over-score) were measured against macOS 26.3's *older* model.

If the new model grades well by itself, you get the no-download, low-battery win
with **no adapter, no toolkit, no entitlement, no version pinning.**

## Why a separate app

Importing FoundationModels for the system model and raising `deploymentTarget`
would strand iOS 26 users — the exact packaging wall that made the earlier Core
AI branch unmergeable. This target ships to nobody and never touches
MedAdvisor's code or its inference path.

## What it does / does not do

- Replays the **exact 48 benchmark prompts** from `Resources/bench_prompts.json`
  (generated by the Python harness from `realistic_cases.json` +
  `rubrics/outpatient-clinic.json` via `app_scoring.build_prompt`), so there is
  zero prompt logic re-implemented in Swift and nothing can drift.
- Records raw output, per-call latency, output tokens, thermal state, battery.
- Reads `SystemLanguageModel.contextSize` — the authoritative context window
  (Apple's WWDC26 session shows 8192; we measured ~4096 on macOS 26.3).
- Uses **default guardrails** so refusals are measured honestly, and **greedy**
  sampling to match every other run in the table.
- **Scores nothing.** Ground-truth labels are not in this app. Metrics are
  computed on the Mac by `score_ios_probe.py` using the app's own parser and
  evidence guardrail, so the result is directly comparable to Qwen, stock FM on
  macOS, and the adapter runs.

## Run it (on the Air, ~10 minutes)

```bash
# 1. on the Air, after pulling the ane-experiment branch
cd tools/ios-fm-probe
xcodegen generate          # brew install xcodegen if needed
open FMProbe.xcodeproj
```

2. Select your iPhone as the run destination. If Xcode complains about signing,
   set the target's Team (or add `DEVELOPMENT_TEAM` in `project.yml`).
3. Build & run on the phone. Confirm **Settings → Apple Intelligence & Siri** is
   enabled, then tap **Run 48-decision probe**. Takes a few minutes; keep the
   app foregrounded (the ANE needs foreground, and the probe holds the screen
   awake).
4. Tap **Share results JSON** → AirDrop `fm_probe_ios.json` to the mini.

No Xcode? Create a new iOS App project manually, drop in
`Sources/FMProbeApp.swift` and `Resources/bench_prompts.json`, set the
deployment target to 26.4+.

## Score it (back on the mini)

```bash
cd tools/llm-benchmark
.venv/bin/python score_ios_probe.py ~/Downloads/fm_probe_ios.json
```

Prints the on-device row next to every other model measured, plus the context
size, refusal count, tok/s, thermal transition, and battery cost — the last
three being things no Mac run can tell you, and the original motivation for the
whole experiment (the llama.cpp path costs ~5%/analysis and hits "serious").

## Regenerating the prompts

Only needed if `realistic_cases.json`, the rubric, or `app_scoring.py` changes:

```bash
cd tools/llm-benchmark && .venv/bin/python - <<'EOF'
import json; from pathlib import Path
from app_scoring import build_prompt
H = Path.cwd(); R = H.parent.parent
crit = {c["id"]: c for c in json.loads((R/"rubrics/outpatient-clinic.json").read_text())["criteria"]}
cases = json.loads((H/"realistic_cases.json").read_text())
out = [{"id": f"{c['id']}:{k}", "prompt": build_prompt(crit[k], c["flat"])}
       for c in cases for k in c["labels"]]
(H.parent/"ios-fm-probe/Resources/bench_prompts.json").write_text(json.dumps(out, indent=1, ensure_ascii=False))
print(len(out), "prompts")
EOF
```
